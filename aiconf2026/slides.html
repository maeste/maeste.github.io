The failure story
// it worked on my machine → it worked in my prompt
The shift in one line

"It worked on my machine" → "It worked in my prompt."

An agent ships plausible, confident work. Nothing in the repo pushed back. By the time a human notices, it's a PR — or worse, it's merged.

The failure is almost never the model. It's the environment the model ran in.

"The agent didn't fail your repo.
Your repo failed the agent." — and that's a thing you can measure, and fix.

A compass (my newsletter)

Harness = space. Loop = time + decision.

Harness — the space

The limits within which the agent moves. What it's allowed to do, what it can reach, how its work gets checked.

Sandbox · permissions · tools · tests · evals

Loop — the time + decision

How many times to repeat, and when to stop. A loop is not an automation — a loop has a decision inside it.

Trigger · goal · verifier · state

An agent is a process running inside a second-level operating system — the harness draws the limits, the loop manages the process.

The reversal

You don't buy a harness.
Most of it is already in your repo — usually broken.

The full harness is LLM + repo + external apparatus (sandbox, skills, MCP, evals). You can't own the model or the cloud runtime. You own the repo. That's the slice worth measuring.

04 / 07
✅ VALIDATE — the verifier
// the decision that lets a loop converge
The testing paradox

Tests aren't for finding bugs.
They're the agent's stop condition.

Without a verifier

  • Agent writes code
  • You manually verify everything
  • Bottleneck. Fatigue. Mistakes.
  • No convergence — just repeated prompting. Vibes.

With a verifier

  • Agent writes code
  • Agent runs the check → pass
  • You review the PR confidently
  • The loop can decide when it's done.

"The verifier is the difference between a loop and a vibe." — without it, a human is the stop condition, every time.

Loop-driven development

It's TDD — at a larger unit of intent.

Same shape, bigger thing wrapped: a task, a PR, a migration, a labeled backlog. Failing check → make it pass → refactor.

makerthe agent that writes the code
checkera separate worker that grades it
why separatea model reviewing its own work passes almost everything

The verifier can even be a different model than the coder — an architecture decision, not a single bet on one "best" agent.

A strong /goal reads like a contract

A good verifier specifies four things. Leave any vague…

end statetests in test/auth pass
evidenceexit code 0, green CI
constraintstouch only app/api/billing
budgetmax 20 turns · 5 min

…and the model fills the gap with the easiest reading: stops early, takes a shortcut, or redefines success so the transcript looks done while the system is broken.

VALIDATE is where the money leaks

Iterations are the budget line — not tokens.

1× vs 6× A loop that retries six times before converging costs six times one that lands first pass — same model.

"A weak verifier is the most expensive bug you can ship." A loose check stops early on broken work, or grinds on work already done — whole iterations wasted.

You used to tune the prompt. Now you tune the loop — that's where the cost accumulates.

05 / 07
🛡 SECURE — the boundaries
// a loop without boundaries is dangerous
The space the agent can move in

Autonomy scales with blast radius.
Bound it, or don't delegate.

Sandbox & isolation

  • Committed devcontainer
  • A documented execution policy
  • Host-level sandbox counts — if it's in the repo

LINCE.sh — a documented, repeatable OS-level sandbox. It earns the score precisely because it's reproducible, not because it's magic.

The under-investment

  • SECURE is the most skipped axis
  • And the one that blocks real delegation
  • You won't let a loop run unattended if you can't confine it

Credit is for evidence in the repo, not self-report. No unverifiable —sandbox flag.

The rest of the boundary

Secrets, supply-chain, and what the agent is allowed to do.

🔒 Secret hygiene.gitignore secrets · .env.example · committed lockfiles
📦 Supply-chainDependabot / Renovate · pinned versions
💉 Injection & permstrusted files only · restrictive agent deny rules

"You can't delegate what you can't confine."
